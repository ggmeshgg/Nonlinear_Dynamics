# Strogatz solving club

Это общий репозиторий симуляций, решений и заметок по нелинейной динамике.
Сайт: https://ggmeshgg.github.io/Nonlinear_Dynamics/

## Как добавить новую страницу

1. Обнови репозиторий и создай отдельную ветку для работы.
2. Создай папку с коротким именем, например `pendulum/`. Для обычной
   симуляции достаточно `index.html`, CSS и JavaScript. Добавь `README.md`
   с описанием модели, предположений и упражнения. PDF и его исходники
   положи в `paper/`. Симуляция должна работать прямо в браузере.
3. Используй относительные ссылки: `styles.css`, `app.js`, `paper/solution.pdf`.
   Добавь ссылку `../` обратно на главную. Адрес проекта на сайте будет
   `/Nonlinear_Dynamics/pendulum/`, поэтому `/assets/` и `/paper/` не подходят.
4. Добавь карточку в `.project-grid` корневого `index.html` и строку в
   таблицу корневого `README.md`. Ссылайся только на существующие материалы;
   кратко и точно опиши, что моделируется.
5. В `scripts/build.mjs` добавь имя статической папки в список
   `['fireflies', 'liquid-level']`: сборка скопирует её в `dist/`.
   Если проекту нужен сборщик, собирай его с базовым путём
   `/Nonlinear_Dynamics/<имя>/` и копируй результат и материалы в `dist/<имя>/`.
   Установку его зависимостей добавь в `package.json` → `setup`; при
   необходимости дополни пути кеша в `.github/workflows/pages.yml`.
6. Проверь локально, отправь ветку и открой pull request в `main`.
   После слияния GitHub Actions сам опубликует сайт. Если пользователь
   прямо попросил пушить в `main`, отдельный PR не нужен.

## Проверка и публикация

Используй Node.js 24 (версия записана в `.tool-versions`). Из корня:

```sh
npm run setup
npm run build
npm run preview
```

Открой `http://127.0.0.1:4173/Nonlinear_Dynamics/`. Проверь карточку,
новую страницу, основные элементы управления симуляцией, ссылку назад и все PDF.
Посмотри на узком экране и убедись, что нет ошибок загрузки ресурсов.
При изменении математики проверь известное равновесие или другой
независимо вычисленный результат; запускай существующие тесты проекта.

После публикации дождись успешного `Publish club site` в GitHub Actions
и повтори основные проверки на живом URL. Успешная сборка сама по себе
не доказывает, что страница работает на сайте. В отчёте различай:
сделано локально, отправлено в репозиторий, опубликовано, проверено в браузере.

## Держи просто

- Каждый проект живёт в своей папке; общие главная и сборка — в корне.
- Предпочитай обычные HTML/CSS/JS. Не добавляй фреймворк или общий движок
  без необходимости; не переделывай соседние проекты ради новой страницы.
- Не коммить `node_modules/`, `dist/`, секреты и личные данные.
- `gas-the-room/` и `rlc-interactive-lecture/` импортированы с историей:
  меняй их здесь.
  Для сайта используется корневой workflow, а не вложенный workflow проекта.
